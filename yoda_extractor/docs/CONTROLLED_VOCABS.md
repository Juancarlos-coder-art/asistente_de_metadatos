# Controlled Vocabularies

Structured reference lists used to map free-text metadata fields to standardized linked-data URIs.

---

## Fetching / updating vocabularies

```bash
python controlled_vocabularies/fetch_vocabularies.py
```

The orchestrator reads `list_vocabularies.csv` and dispatches each row to the right fetcher based on `Mode_extracted_JSON`. Mode extracted JSON only for generating the summary json of the vocabulary. Personal data has its own extractor of the vocabulary:

```
controlled_vocabularies/
  fetch_vocabularies.py          ← entry point (orchestrator)
  fetchers/
    iterative.py                 ← Mode = Iterative  (fetches RDF endpoints over the network)
    personal_data.py             ← Mode = Personal_data  (parses bundled RDF locally, no network)
  build_vector_db.py             ← preload script for the RAG vector tables
  vocabs/                        ← generated JSON files (one per vocabulary)
  db/                            ← embedded LanceDB (generated, git-ignored)
  list_vocabularies.csv
  personal_data.rdf              ← bundled RDF for personal data
```

| Mode | Fetcher | Description |
|------|---------|-------------|
| `Iterative` | `fetchers/iterative.py` | Fetches root RDF, discovers concept URIs, then fetches each one individually |
| `Personal_data` | `fetchers/personal_data.py` | Parses the local `personal_data.rdf` — no network required |

## JSON format

Each file is a map from concept code to its extracted fields:

```json
{
  "PHDR": {
    "uri": "https://hdeu-dcat.acceptance.data.health.europa.eu/resource/authority/healthcategories/PHDR",
    "prefLabel": "Data from population-based health data registries such as public health registries"
  },
  "EHCT": {
    "uri": "https://hdeu-dcat.acceptance.data.health.europa.eu/resource/authority/healthcategories/EHCT",
    "prefLabel": "Data from clinical trials...",
    "definition": "..."
  }
}
```

Fields extracted (English only, duplicates across fields removed — first wins):

| RDF predicate | JSON key |
|---------------|----------|
| `skos:prefLabel` | `prefLabel` |
| `skos:definition` | `definition` |
| `dct:description` | `description` |

If a concept has multiple values for the same predicate they are stored as a list; single values are stored as a string.

## Vocabulary Matcher

For each vocabulary in `list_vocabularies.csv`, the `VocabularyMatcher` extractor selects the best-matching URI for the current dataset. The strategy is chosen per vocabulary via the **`Metadata-Processed-By`** column:

| `Metadata-Processed-By` | Strategy |
|-------------------------|----------|
| `LLM` | One LLM call per vocabulary |
| `RAG` | Embedding similarity search over a precomputed LanceDB table |

### Output cardinality

Each vocabulary row declares its output shape via two CSV columns:

| Column | Values | Effect |
|--------|--------|--------|
| `multiple_output` | `true` / `false` | Whether the field returns an array of URIs (`true`) or a single URI string (`false`) |
| `top-n` | integer | Maximum number of results returned when `multiple_output=true`. Ignored when `multiple_output=false`. |

When `multiple_output=false` the best single match is returned (or the field is omitted if nothing fits, with NO array as output). When `multiple_output=true` up to `top-n` matches are returned as an array (may be empty `[]`).

### LLM strategy

1. Loads the vocab JSON from `controlled_vocabularies/vocabs/<feature>.json`.
2. Calls the LLM with the dataset's `title_en_tmpt`, `notes_en_tmpt`, and `keyword_en_tmpt` plus the **full vocabulary JSON** (all fields per entry, minus `uri`).
3. **`multiple_output=false`**: the LLM returns the single best-matching code (or `"NONE"`). The full URI is composed as `<base_url>/<code>`.
4. **`multiple_output=true`**: the LLM returns a JSON array of up to `top-n` codes (or `[]`). Each valid code is composed into a URI; unknown codes are logged as warnings.

LLM prompts are logged at DEBUG level — run with `--log-level DEBUG` to inspect them.

Falls back to `title` / `notes` / `keyword` (Spanish) if the English versions are empty.

### RAG strategy

A local, free embedding model (**all-MiniLM-L6-v2**, 384 dims) plus an embedded **LanceDB** database (`controlled_vocabularies/db/`). One table per vocabulary, built ahead of time:

1. **Preload** (`build_vector_db.py`): for each vocab entry, joins all fields except `uri` into one text, embeds it, and stores `{code, text, uri, vector}` in the table `<feature>`.
2. **Runtime**: embeds the dataset's `purpose_en_tmpt`, `title_en_tmpt`, `notes_en_tmpt`, `keyword_en_tmpt` into one query vector, runs a nearest-neighbour search with `limit=top-n`.
3. **Distance filtering**: only hits whose distance is within `1.2×` the best hit's distance are kept. This relative threshold avoids having to calibrate an absolute cutoff.
4. **`multiple_output=false`**: returns only the closest URI as a string. **`multiple_output=true`**: returns all kept URIs as an array.

The embedding model is downloaded and cached locally by `sentence-transformers` on first use. The database is rebuildable, so `controlled_vocabularies/db/` is git-ignored.

```bash
# (re)build the vector tables — run once, or whenever a vocab JSON changes
python controlled_vocabularies/build_vector_db.py
```

### Input fields used

| Strategy | Fields | Source |
|----------|--------|--------|
| LLM | `title_en_tmpt`, `notes_en_tmpt`, `keyword_en_tmpt` | `llm_metadata` extractor |
| RAG | `purpose_en_tmpt`, `title_en_tmpt`, `notes_en_tmpt`, `keyword_en_tmpt` | `llm_metadata` extractor |

### Output example

```json
{
  "health_category": [
    "https://hdeu-dcat.acceptance.data.health.europa.eu/resource/authority/healthcategories/RPDG",
    "https://hdeu-dcat.acceptance.data.health.europa.eu/resource/authority/healthcategories/MRMR"
  ],
  "dcat_type": "http://publications.europa.eu/resource/authority/dataset-type/HVD",
  "health_theme": [
    "http://13.81.34.152:1101/resource/authority/health-theme/CLIMATE_HEALTH"
  ],
  "coding_system": {
    "uri": "https://hdeu-dcat.acceptance.data.health.europa.eu/resource/authority/coding-system/SNOMED-CT",
    "label": "SNOMED-CT"
  },
  "code_values": ["SNOMED-CT"],
  "conforms_to": "https://hdeu-dcat.acceptance.data.health.europa.eu/resource/authority/standard/FHIR",
  "personal_data": [
    "https://w3id.org/dpv/pd#MentalHealth",
    "https://w3id.org/dpv/pd#MedicalHealth"
  ]
}
```

`multiple_output=true` fields always return an array (may be empty `[]`). `multiple_output=false` fields return a single value or are omitted if nothing fits. `coding_system` returns an object `{"uri": "...", "label": "<last URI segment>"}` instead of a plain string. `code_values` is derived automatically from `coding_system` and returns an array with just the label string (e.g. `["SNOMED-CT"]`); it is skipped if already prefilled via `--input-json`. Errors are accumulated into the global `errors` array.

`spatial` uses two LLM calls and resolves four geographic levels from `vocabs/locations.json`:

**Call 1 — `spatial_tmpt` (inside `LLMExtractor`):** Given the sample records, the LLM produces a free-text description in English of the geographic coverage observed in the data values (e.g. _"The dataset contains patients from several Spanish provinces including Madrid, Barcelona and Valencia"_). This description is the primary input for the second call.

**Call 2 — spatial resolution (inside `VocabularyMatcher`):** The LLM receives `spatial_tmpt` plus title/notes/keywords as fallback, and the keys of each geographic level as candidate lists. It returns a JSON object with four arrays.

| Level | LLM input | URI construction |
|-------|-----------|-----------------|
| Provinces | List of names (keys) from `locations.json` | Value from `locations.json["provinces"]` |
| Autonomous communities | List of names (keys) from `locations.json` | Value from `locations.json["autonomies"]` |
| Countries | ISO 3166-1 alpha-3 codes | `http://publications.europa.eu/resource/authority/country/{CODE}` |
| Continents | List of names (keys) from `locations.json` | Value from `locations.json["contients"]` |

**Threshold cascade (most specific → least specific):** If the detected entries at a level exceed **30%** of the total available entries at that level, that level is skipped and the next one (less specific) is used instead. Continents have no threshold — all matches are always included.

| Level | Total available | 10% threshold |
|-------|----------------|---------------|
| Provinces | ~50 | ~5 |
| Autonomous communities | 19 | ~2 |
| Countries | 50 (world) | ~5 |
| Continents | — | no threshold |

Example: if 15 provinces are detected → exceeds 10% of ~5 → skip provinces, use autonomies. If autonomies also exceed threshold → use countries. If countries also exceed threshold → use continents.

**Default:** if no match is found at any level, defaults to `["http://publications.europa.eu/resource/authority/country/ESP"]`.

All matched URIs are combined into a single deduplicated array.

### Edge cases

| Situation | Behaviour |
|-----------|-----------|
| Vocab JSON not found (LLM) | Field skipped, error added to global `errors` |
| LLM returns `NONE` or `[]` | Field omitted |
| LLM returns unknown code(s) | Unknown codes skipped, warning added to `errors`; known ones still returned |
| LLM call fails | Field omitted, error added to global `errors` |
| Vector table missing (RAG) | Field skipped, error added — run `build_vector_db.py` |
| RAG search fails | Field omitted, error added to global `errors` |
| No hits pass distance filter (RAG) | Field omitted |
| No metadata available | Field skipped |

## Adding a new vocabulary

1. Add a row to `list_vocabularies.csv` with the appropriate columns:
   - `Mode_extracted_JSON`: fetch mode (`Iterative` or `Personal_data`)
   - `Metadata-Processed-By`: match strategy (`LLM` or `RAG`)
   - `multiple_output`: `true` if the field should return an array, `false` for a single string
   - `top-n`: maximum results when `multiple_output=true` (ignored otherwise)
2. Run `python controlled_vocabularies/fetch_vocabularies.py` — the JSON is generated automatically.
3. If the new vocabulary uses `RAG`, run `python controlled_vocabularies/build_vector_db.py` to (re)build its vector table.
4. No code changes needed.
